# Aviator Telegram Analyzer — V12 (Spribe Aviator، اللعبة 52358 فقط)

أداة **بحث وجمع بيانات** لجولات Aviator المكتملة، مع تحقق صارم من العدالة (Provably Fair) وتنبيهات Telegram.
لا تحتوي على أي نموذج "يتنبأ" بالنتيجة: كل ما تعرضه احتمالات إحصائية مُجمَّدة قبل الجولة ومُقيَّمة لاحقًا بشفافية.

## البنية
| المكوّن | الوظيفة |
|---|---|
| `collector.py` | يفتح Chrome، يفك كل حزم SmartFox في كل إطار WebSocket، ويخزن النتائج فورًا. لا يتواصل مع Telegram. |
| `bot.py` | يقرأ صندوق الإرسال (outbox) من SQLite ويرسل التنبيهات. فشل Telegram لا يوقف الجمع. |
| `aviator/` | الحزمة الأساسية (التخزين، التحقق، الحالة، التنبؤ، التقييم، الإحصاءات). |
| `scripts/` | الترحيل، الإصلاح، التقارير، الدفعات، فحص البيئة. |
| `tests/` | اختبارات وحدات + إعادة تشغيل (replay) حتمية. |

## مصدر النتائج (القاعدة الذهبية)
- الجولة المكتملة تُحفظ **فقط** من `roundChartInfo` (`roundId` + `maxMultiplier`) أو من `init.roundsInfo` (تعبئة تاريخية، تُوسم `origin=backfill`).
- رسائل الرهانات/السحب (cashout) ورسائل Crash/SignalR العامة **لا** تُعتبر نتائج أبدًا.
- `roundId` يجب أن يكون رقمًا صحيحًا موجبًا، والمضاعف ≥ 1.00 بخانتين عشريتين كحد أقصى.
- كل جولة لها صف واحد (مفتاح فريد). التكرار يُحسب كتأكيد، والتعارض يُحجَز ولا يستبدل الأصل.

## التثبيت (Windows)
1. ثبّت Python 3.10 أو أحدث وGoogle Chrome.
2. فك الضغط في **مجلد جديد** (لا تفكه فوق النسخة القديمة).
3. انسخ ملفات البيانات القديمة (`rounds.json`, `history.json`, `seeds.jsonl`, `subscribers.json`, …) إلى مجلد `legacy\` داخل المشروع.
4. شغّل `install.bat`: ينشئ `.venv`، يثبت المتطلبات المثبتة الإصدار، يكتب `requirements.lock.txt`، يفحص `sfs2x-py`، ثم يرحّل البيانات القديمة.
5. التوكن: شغّل `set_token.bat` (يكتب `.env` المحلي المستبعد من git) أو اضبط متغير البيئة:
   `setx TELEGRAM_BOT_TOKEN "123456:ABC..."` ثم افتح نافذة جديدة. **لا تضع التوكن في config.json** (يتم تجاهله).
6. شغّل `run_all.bat` (نافذتان: الجامع والبوت) أو كل واحد على حدة.

## الأوامر
| ملف | الوظيفة |
|---|---|
| `run_collector.bat` | الجامع فقط (يعيد الاتصال تلقائيًا مع تأخير متزايد) |
| `run_bot.bat` | البوت فقط |
| `migrate.bat` | ترحيل البيانات القديمة (آمن للتكرار، لا يحذف شيئًا). يقبل `--legacy-dir PATH` |
| `repair.bat` | فحص السلامة، إكمال rounds.jsonl الناقص بالإلحاق فقط، توليد الدفعات الناقصة، إعادة التحقق |
| `report.bat` | تقرير إحصائي + تقييم زمني |
| `run_tests.bat` | تشغيل الاختبارات |

أوامر Telegram: `/start` `/stop` `/status` `/last` `/stats` `/predict` `/round` `/verify <id>` `/add` `/manual` `/clear confirm`.
- `/add` يكتب في جدول `manual_entries` فقط، ولا يدخل البحث أو التنبؤ.
- `/clear confirm` يحذف إدخالاتك اليدوية فقط. `/clear confirm all` لمعرّفات `admin_chat_ids` فقط. بيانات البحث لا تُحذف أبدًا من البوت.

## التنبؤ (بدون تسريب)
- يُجمَّد التقدير للجولة R **فقط** عند `changeState` مع `newStateId = 1` للجولة R.
- الميزات = الجولات ذات `round_id < R` المخزنة قبل لحظة التجميد. نتيجة R غير متاحة إطلاقًا.
- يُسجل التقدير (مع hash للميزات) قبل النتيجة، ثم تُرفق النتيجة لاحقًا في حدث منفصل.
- فحص التسريب: إن كانت أي ميزة ≥ R أو كان التجميد بعد معرفة النتيجة يُعلَّم `leak_flag=1` ويُستبعد من التقييم.
- النماذج: `theoretical` (P(X≥t)=0.97/t بالضبط وفق المعادلة)، `empirical_all`، `empirical_recent` (Beta-binomial). تم **حذف LightLSTM** لأنه لم يكن مدرَّبًا فعليًا.
- التقييم: walk-forward زمني + log loss + Brier + معايرة (calibration) لكل عتبة.

## التحقق من العدالة
- SHA-512(server_seed + seed1 + seed2 + seed3) بالضبط، بدون فواصل وبدون nonce.
- المضاعف = max(1.00, floor(97·2^52/(2^52−h))/100)، حيث h = أول 13 خانة hex.
- `verified=true` فقط إذا أُعيد إنتاج مضاعف **نفس الجولة** المسجلة، مع ثلاث بذور لاعبين بالضبط، وتطابق الالتزام SHA-256 (إن وجد) وتطابق hash الجولة (إن وجد).
- الدليل يُربط بجولة فقط إذا كان `roundId` في نفس الكائن (مثل `fairness.roundId`). بدون ذلك يُحفظ "غير مرتبط" ولا يُستخدم.
- الجولة الموثّقة مقفلة؛ أي دليل متعارض لاحق يُحجز للمراجعة.
- الضغط التلقائي على نافذة العدالة **معطّل** افتراضيًا (`fairness_autoclick: false`).
- ملاحظة: Spribe لم تنشر رسميًا معادلة تحويل الـ hash إلى مضاعف؛ المعادلة أعلاه هي إعادة البناء المعتمدة (97% RTP). إذا اختلفت، لن تظهر الجولة "موثّقة" (فشل آمن).

## الأمان
- لا يُرفع إلى git: `chrome_profile/`، `.env`، `data/`، `logs/`، ملفات التشغيل القديمة (انظر `.gitignore`).
- السجلات تخفي الحقول الحساسة (token, cookie, session, password…).
- عند الترحيل تُحذف قيمة `bot_token` من نسخة config المحفوظة.

## حدود معروفة
- `sfs2x-py` لم يُختبر هنا على حزم حقيقية من هذا الموقع؛ إذا كانت الجلسة مشفرة (AES) قد يفشل الفك في Python، ويبقى مصدر Chrome (SmartFox hook) يعمل. `check_env.py` و`logs/network` يوضحان ذلك.
- أسماء الحقول داخل `init.roundsInfo` مفترض أنها مطابقة لـ `roundChartInfo` (`roundId`, `maxMultiplier`). أي عنصر مختلف يُحجز ولا يُخمَّن. راجع `quarantine` بعد أول تشغيل.
